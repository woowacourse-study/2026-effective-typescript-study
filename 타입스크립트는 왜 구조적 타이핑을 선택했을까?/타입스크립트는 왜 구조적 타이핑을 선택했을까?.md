## 1. 자바스크립트의 덕 타이핑

자바스크립트는 덕 타이핑(Duck Typing) 기반의 언어이다.

덕 타이핑이란 “오리처럼 걷고, 오리처럼 소리를 낸다면 그것은 오리다.” 라는 말에서 유래한 개념이다. 객체가 어떤 타입인지보다 필요한 속성이나 기능을 가지고 있는지를 기준으로 동작한다.

그래서 만약 함수가 필요로 하는 값과 기능만 가지고 있다면, 그 객체가 어떤 방식으로 만들어졌는지는 중요하지 않다.

```typescript
fuction introduce(person) {
	console.log(`${person.name}입니다.`);
}

const person = {
  name: "윤석",
  school: "우테코",
};

const student = {
  name: "윤석",
  nickname: "윤돌",
};

introduce(person);
introduce(student);
```

introduce 함수는 객체에 name 속성만 존재하면 정상적으로 동작한다.

즉, 객체의 식별자나 생성 방식이 아닌, 필요한 속성을 가지고 있는지가 중요한 것이 자바스크립트의 덕 타이핑이다.

## 2. 타입스크립트는 왜 구조적 타이핑을 선택했을까?

이러한 자바스크립트의 특성 때문에, 타입스크립트 역시 객체의 식별자보다 구조를 기준으로 타입을 판단하는 구조적 타이핑을 채택했다.

그 이유는 타입스크립트가 자바스크립트의 상위 집합 관계(Superset)이기 때문이다.

이미 존재하는 자바스크립트 코드는 객체의 구조만 맞으면 자유롭게 사용하도록 작성되어 있다. 만약 타입스크립트가 객체의 식별자를 기준으로 타입을 검사한다면, 기존 자바스크립트 코드의 대부분이 타입 오류가 발생했을 것이다.

타입스크립트는 자바스크립트의 런타임 동작을 바꾸지 않으므로, 호환성을 유지하기 위해 객체의 식별자가 아닌 구조를 기준으로 타입을 판단하는 방식을 선택했다.

## 3. 타입스크립트의 구조적 타이핑

앞에서 살펴본 것처럼 타입스크립트는 객체의 식별자가 아닌 구조를 기준으로 타입을 검사한다.

```typescript
interface Person {
  name: string;
}

function introduce(person: Person) {
  console.log(`${person.name}입니다.`);
}

const person = {
  name: "윤석",
  school: "우테코",
};

const student = {
  name: "윤석",
  nickname: "윤돌",
};

introduce(person);
introduce(student);
```

타입스크립트에서도 person과 student는 모두 name: string 이라는 구조를 만족하므로, Person 타입과 호환된다. 즉, 객체의 식별자가 아니라 구조를 기준으로 타입을 판단하는 것이 구조적 타이핑이다.

## 4. 구조적 타이핑의 한계

구조적 타이핑은 유연하다는 장점이 있지만, 객체의 구조만 검사할 뿐 의미까지는 검사하지 못한다.

```typescript
interface Vector2D {
  x: number;
  y: number;
}

interface Vector3D {
  x: number;
  y: number;
  z: number;
}

function calculateLength(vector: Vector2D) {
  return Math.sqrt(vector.x ** 2 + vector.y ** 2);
}

const vector3D: Vector3D = {
  x: 3,
  y: 4,
  z: 5,
};

calculateLength(vector3D);
```

calculateLength는 Vector2D를 매개변수로 받지만, Vector3D를 전달해도 타입 오류가 발생하지 않는다.

이유는 Vector3D가 x와 y를 모두 가지고 있어 Vector2D의 구조를 만족하기 때문이다.

하지만 함수 내부에서는 z 값이 전혀 사용되지 않는다. 그리고 결과로 나온 값은 의도한 결과와 다른 값이 나올 것이다.

즉, 타입스크립트는 구조만으로 모든 의도를 표현할 수 없다.

따라서 구조적 타이핑을 사용할 때는 타입 호환성과 코드의 의도가 항상 일치하지 않을 수 있다는 점을 이해해야 한다.

## 5. 마무리

결국 자바스크립트의 자유도를 보완하기 위해 타입을 도입한 타입스크립트도, 자바스크립트의 상위 집합 관계라는 특성 때문에 완전히 닫힌 타입 시스템을 선택하지 않았다.

이러한 구조적 타이핑 덕분에 필요한 속성만 잘 가지고 있다면 더 많은 정보를 가진 객체도 유연하게 사용할 수 있는 장점도 있지만, 결국 객체의 구조만 판단할 뿐 개발자의 의도까지는 알 수 없다는 한계도 존재한다.

구조적 타이핑은 식별자가 아닌 구조를 기준으로 판단한다. 그렇기 때문에 개발자의 의도를 전달하기 위해서는 식별자와 타입을 더 신중하게 설계해야 한다고 느꼈다. 어떻게 하면 의도가 잘 드러나는 타입을 설계할 수 있을지 생각해봐야겠다.
